# Computational Substrate Blocker Clearance Decision Record

Status: completed closeout decision

## Decision

Close the four-blocker clearance program as executed and reassessed.

Do not launch a broad-ownership follow-on program yet.

The program succeeded in turning the original blocker list into a cleaner,
smaller, better-proved current boundary, but it did not justify a new broad
authority or ownership expansion beyond the already-admitted bounded slice.

## What The Program Settled

### Phase 1: Same-Sheet Shared Authoring

The targeted named-range-combined regroup and merge attempt families were
checked against live Calc and did not close as distinct live widening
families.

That means the current broader same-sheet frontier is now blocked by real
live-shape non-closure, not by lack of investigation.

### Phase 2: Repair-Sensitive Normalization

The repair-sensitive frontier is no longer one opaque bucket.

It now breaks cleanly into:

- deterministic `RepairDetected` rollback
- explicit reject-by-rule
- retained host-only cleanup diagnostics

### Phase 3: Off-Sheet Dependency Closure

The off-sheet frontier is now an explicit defer-or-reject boundary rather
than a near-miss admission.

Future off-sheet work has to start with canonical cross-sheet dependency,
broadcaster, queue, rollback, and verification closure.

### Phase 4: Host-Shell Reduction

The retained host shell is no longer a top opaque blocker on the admitted
slice.

It is now better described as a settled execution-and-observation shell
around engine-authored records for realization, rollback, live apply,
primitive execution, and final verification.

## Result Against The Original Ambition

The original blocker-clearance plan was intentionally ambitious. It aimed to
clear all four blockers strongly enough to support a materially wider
admitted slice and at least one bounded off-sheet admission.

That full success bar was not reached.

The program outcome is instead:

- broader same-sheet shared-group widening remains unresolved
- repair-sensitive normalization remains explicit but unresolved
- off-sheet dependency closure remains unresolved
- retained host shell is no longer one of the top blockers

This is still a successful closeout in the architectural sense because the
program replaced a vague four-blocker picture with three concrete technical
frontiers plus one settled contract boundary.

## Current Remaining Top Blockers

The remaining top blockers for admitted-slice widening are now:

1. exact after-state authoring for broader same-sheet shared-group families
2. repair-sensitive normalization that can close exactly without hidden host
   cleanup
3. bounded off-sheet dependency closure with exact rollback and final
   verification

The retained host shell remains important, but it is no longer on this top
blocker list.

## Broad-Ownership Reassessment

A broad-ownership follow-on program is not justified yet.

The admitted slice is meaningful and ownership-complete on its bounded
surface, but the blocker-clearance program did not establish:

- broader same-sheet exact closure
- bounded off-sheet admission
- any reason to reinterpret the retained host document shell as ready for
  large-scale transfer

The next roadmap should therefore return to smaller targeted widening passes
instead of another omnibus broad-ownership push.
